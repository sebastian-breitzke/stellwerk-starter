# Skill Blueprint: Doc Writing

Doc Writing is for creating or reshaping Markdown and prose so people can scan,
understand, and act.

## Purpose

Improve documentation structure, not prose decoration.

Optimize for:

- fast scanning first
- deep reading second
- clear hierarchy
- one obvious next step
- low cognitive load

## Document Modes

| Mode | Use For |
|------|---------|
| Tutorial | guided learning |
| How-to | completing a task |
| Reference | exact lookup |
| Explanation | understanding why |

Pick the dominant mode instead of mixing all four equally.

## Rules

- Put the most important point early.
- Use descriptive headings.
- Keep one section to one question.
- Prefer short lists of related items.
- Keep examples realistic but safe.
- Preserve technical accuracy over nicer wording.

## Review Questions

- Can a reader understand purpose and next step in 60 seconds?
- Is this for humans, agents, or both?
- Is agent-facing instruction separated from human explanation?
- Are private details removed?
- Are links and commands still accurate?
