# Skill Blueprint: Meeting Recap

Meeting Recap turns transcripts or rough notes into useful follow-up material.

## Purpose

Produce:

- a shareable recap
- decisions and commitments
- action items with owners when known
- open questions
- risks and sensitivities
- optional private reflection for the user
- optional person-context suggestions for review

## Boundary

Separate shareable facts from private interpretation.

Do not create:

- gossip files
- political dossiers
- performance judgments
- psychological labels
- chronological transcript archives by default

## Output Modes

| Mode | Use For | Output |
|------|---------|--------|
| Quick | short call | key facts, decisions, actions |
| Standard | normal meeting | recap plus private reflection if useful |
| Customer | customer/project call | needs, commitments, risks, next step |
| Partner | partner/vendor call | alignment, expectations, follow-up |

## Shareable Recap

Include only sections supported by the input:

- context
- participants and roles
- key facts
- decisions
- commitments
- action items
- open questions
- risks or sensitivities
- next best move

Write in the meeting language unless the user asks otherwise.

## Private Reflection

Use a separate section or file only when useful.

Focus on:

- next move
- weak framing
- unclear commitments
- missed follow-up
- preparation for the next conversation

Keep it practical. Do not turn it into people scoring.

## Person Context Suggestions

Suggest durable collaboration memory only as review candidates:

```text
Person Context To Review:

- <Person>: check whether this is durable: <communication or collaboration signal>
```

Do not persist person context without explicit user approval.
