# Work Policy Blueprint: Change Workflow

Use a small, explicit change flow for coding-agent work.

## Before Editing

- Read local agent instructions.
- Check repo status.
- State the owned area.
- Identify the current healthy pattern.
- Plan verification.

## During Work

- Keep changes tied to the request.
- Prefer one current path over compatibility layers.
- Do not copy a legacy pattern just because it is nearby.
- Do not silently change unrelated files.
- Surface unrelated findings at the end.

## After Work

- Run the relevant verification.
- Review the changed files.
- Name remaining risk.
- Leave the workspace state clear for the user.

## External Side Effects

Ask before:

- pushing
- publishing
- sending messages
- deleting data
- deploying
- changing secrets or permissions
